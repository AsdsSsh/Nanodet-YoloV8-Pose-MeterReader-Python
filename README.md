# Nanodet-YoloV8-Pose-MeterReader-Python

[Nanodet-YoloV8-Pose-MeterReader](Nanodet-YoloV8-Pose-MeterReader)的Python版本
公司需要部署一个仪表识别的算法，但是原项目是```C++```版本的,因此写了一个python版本

## 增加的内容

- 增加了OCR读取量程的功能，原来项目中的量程是固定的。用RapidOCR识别表盘上量程两端(左刻度框/右刻度框)旁边的数字，动态得到量程；OCR失败或结果不可靠时自动回退到配置里的静态量程，实际使用的量程会通过JSON输出中的`scale_source`(ocr/config)和`scale_begin`/`scale_end`报告
- 读数补偿改为按量程比例，原来补偿量是固定值。现在补偿的基准和上下限分界都按量程(end - beginning)的比例计算，OCR识别到不同量程时补偿依然保持一致
- 增加了斜拍透视补偿。斜拍时表盘的指针角度会像正弦函数一样被拉伸，补偿项是一个随指针位置变化的正弦项：量程两端和中间为零，在量程的1/4和3/4处最大。默认值-0.4%量程，用于修正斜拍导致读数偏高的问题，可通过`tilt_compensation`参数调整或设为0.0关闭
- 姿态模型找不到量程端点或指针时增加了OCR/图像处理兜底（见上文"识别策略"第2、3级），仅在常规路径(含加边重试)失败后启用，不影响原识别路径
- 模型权重没有做修改，原项目的精度已经够用，场景也很契合

## 识别策略

三级识别，前一级失败才进入下一级：

1. **常规路径**：NanoDet 检测表盘 → YOLOv8-Pose 检指针和量程两端（三类齐全且两端夹角≥30°）→ 按指针角度比例算读数；量程数字用 OCR 读两端附近，失败回退静态配置
2. **OCR 量程端点兜底**：姿态模型检不到量程端点时（如 0 在正左侧的表盘），用 RapidOCR 读整表盘数字，取最小/最大值作端点，按相邻数字分段插值读数
3. **图像处理找指针兜底**：姿态模型连指针都检不到时（如全圆周刻度的千分表），用 Hough 圆定圆心、Canny+Hough 直线找针轴、延伸更长的一侧为尖端，再走第 2 层 OCR 读数

检测侧另有：NMS 按类别（避免指针框压制刻度端框）、重复框合并（同一表盘检出两次时取并集）、全圆周表盘推断顶部 0/100 空隙补全量程。
